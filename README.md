# mira Causal AI — research website

Live site: https://ftamas77.github.io/mira-causal-ai-site/

This repository hosts a static public-facing research website. It presents **mira as a broader causal AI research and engineering initiative**, not as one algorithm or one user interface.

## Pages

- `index.html` — research overview, workflow, journal publications and current usage example.
- `demo.html` — visual industrial cooling example based on reported mira research outputs: 600 observations, 15 temporal links, and evaluation of three explicitly modeled cooling-flow options.
- `images/cooling-*.svg` — accessible, original vector visualizations faithfully illustrating reported demo numbers. These are **illustrations derived from the observed backend report**, not original screenshots.
- `benchmark.html` — separate 900-row blind synthetic comparison and scored results (15 true positives, 3 extras) with transparent limitations.
- `benchmark-v2/` — original reproducibility prompts, code, data and recorded evidence; raw research source materials are not marketing copy.
- `support.html` — GitHub issue-based public feedback. No personal email address is published on the site.
- `privacy.html`, `terms.html` — concise research-stage notices.

## Scientific boundaries

The broader industrial `mira` repository covers preparation, causal discovery, inference, population-level counterfactual workflows and reusable knowledge. The smaller ChatGPT-connected research engine demonstrates a separately implemented subset. The website must never suggest these two codebases are a single validated product.

The cooling decision demo uses a **separately supplied hypothetical structural model**; its coefficients were not learned from the 600-row data. The benchmark is a single author-run synthetic test, not a general performance guarantee. Scientific methods and their limitations are described generically on public pages rather than leading with algorithm branding.

## Website rules

- Keep text concise and visually led. Lead with the analytical question, the verified result and what was actually computed.
- Keep the three peer-reviewed Q1 paper references and the standalone benchmark.
- No invented end users, deployments, clinical impacts, funding or operational results.
- Publishing an authentic chat transcript or original screenshot requires checking personal and proprietary information first.
- Keep hosting, backend, private keys and deployment settings outside this repository.
- Preferred contact is the public GitHub issue tracker. Never solicit private data in a public issue.

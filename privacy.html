Overview. mira Causal AI is an experimental research and education project. Scientific inputs are used to answer the requested calculation, not stored as user profiles or in a project database. Limited operational logs and external platform records are described separately below.

1. Scope and contact

This notice covers the static mira Causal AI website on GitHub Pages and the experimental MCP analysis service hosted on Render. For privacy enquiries, contact Dr. Tamas Fekete at fekete331@gmail.com. This research-contact designation does not describe ownership of the software or research.

2. Information processed

Tool inputs: When a user invokes an analysis, the backend receives structured arguments needed for that operation, such as variable names, time-series observations, graph edges, causal assumptions, context values, candidate interventions and objectives. These fields are not intended to collect names or other personal details, but such data could be included incidentally if a user supplies it.

Application logs: The hosted application records limited technical information such as HTTP method, redacted route category, status code and whether Host/Origin checks passed. Its logging is designed not to contain request bodies, model datasets, full private endpoint paths or credentials. The hosting infrastructure may separately process connection metadata, including IP addresses.

Website traffic: This static site has no project-operated analytics, advertising trackers, user accounts or forms. GitHub Pages nevertheless records visitor IP addresses for security purposes under its documentation and privacy statement.

Correspondence: If you send an email, the sender address and message are used to handle your enquiry. Public GitHub issues are visible to others.

3. Purposes of use

Scientific inputs are processed to validate a supplied graph, perform PCMCI+/ParCorr research discovery or evaluate a specified structural causal model, and return a result to the requesting client. Operational metadata is used for service reliability, security, abuse prevention and troubleshooting. Contact messages are used to reply. mira's backend does not independently acquire external datasets, call an external language model or use tool inputs for its own model training.

Where GDPR applies to incidental personal or technical data, these limited activities support the requested research interaction and the legitimate interests in operating and protecting the service. The project does not seek sensitive personal data.

4. Retention

Submitted model and dataset content: The scientific server is stateless. Inputs and results are handled in memory during execution; they are not persisted in a mira user database, stored session or research-data archive. There is no project-held history of completed user calculations.

Hosting logs: Render retains application logs according to the applicable workspace configuration. Its published standard retention periods are 7 days for Hobby, 14 days for Pro and 30 days for Scale/Enterprise. The actual period depends on the Render workspace plan and whether an external log stream is configured. These provider records are separate from the non-persistent scientific inputs.

GitHub and ChatGPT records: GitHub may retain site-security logs and OpenAI may retain conversation or tool activity under their respective policies and account controls. Their timelines are determined by those providers, not by this research backend.

Email: Enquiry correspondence is retained for the time reasonably needed to respond, handle follow-up or meet applicable legal obligations, then removed when no longer needed. It is not stored in the mira calculation backend.

5. Recipients and hosting

Render hosts the scientific MCP service and operational logs. GitHub hosts the public website and issue tracker. OpenAI / ChatGPT, when used as the client, sends relevant tool requests and receives results under its own applicable terms. The email provider processes voluntary contact correspondence. The project does not sell user data or share scientific inputs with advertising partners.

Those providers may process information in different jurisdictions. Hosting the backend in a European region does not guarantee that every related platform record remains in the EU.

6. Your choices and requests

You can choose not to use the tool and control the structured data supplied to it. Use synthetic, public or appropriately anonymized information. Do not submit health or payment information, government identifiers, credentials, sensitive personal information, or confidential industrial datasets.

To request access, correction, deletion or object to relevant project-handled personal data, contact fekete331@gmail.com; requests will be considered under applicable law. Because the research backend retains no user-linked computation history, it generally cannot retrieve or selectively delete an already completed anonymous calculation. Service-provider logs expire under provider policies.

ChatGPT conversation and connector settings are managed using ChatGPT's controls; GitHub account and platform records follow GitHub's policies. Where applicable, you may contact your national data-protection supervisory authority.

7. Updates

This notice describes the experimental service as of 19 November 2026. It will be revised if the project changes its data practices or hosting arrangements. For appropriate research use, see the Terms of use.

03 / REPRODUCIBLE PROTOCOL

Experimental protocol

Use the authenticated development connector and synthetic data. The demonstration requires access to the local development backend; the public release cannot execute these storage operations.

Prompt sequence and test inputs
  1. In a new chat, create “Synthetic logistics pilot” with a fresh idempotency key. Append rain_mm = 12.5, source_type assumption, source_ref “Synthetic owner-provided pilot value” using the returned ID and revision. Read the record.
  2. In another chat, explicitly select the app, list investigations and retrieve “Synthetic logistics pilot” by title. Report the actual ID, revision and evidence without using chat history.
  3. In the same chat, explicitly select the app again. Append traffic_delay_min = 18, source_type assumption, source_ref “Synthetic traffic scenario” using a new idempotency key and current revision. Retrieve the record.
  4. In a third chat, explicitly select the app, list and retrieve by title only. Report revision and evidence without modification.
Observed integration limitation: some follow-up turns displayed a message-stream error or reported the tool unavailable. Explicit app selection restored operation. The root cause was not established. The four completed checks are not four error-free first attempts.

04 / SCOPE AND LIMITATIONS

Scope and limitations

One authenticated test user, one synthetic record, three conversations. Results are based on actual app execution summaries provided by the author.

Demonstrated

  • Authenticated create, append and read
  • Cross-conversation retrieval
  • Continuation with revisioned evidence and provenance

Still to validate live

  • Token renewal and separate-user isolation
  • Persistence across server restarts and hosted durability
  • Production readiness and client reliability

v0.5.0-dev is a development-preview label, not a released package version. The submitted v0.4.0 release and its existing scientific benchmarks remain separate.
